# Blog builder

This script and Jenkins pipeline are built separately from my blog source, but ideally should just be copied to it so it triggers the build and publishing process. The automation can trigger by leveraging webhooks, scheduled runs or manual triggers via Jenkins.

I am publishing this independently because I want it to be useful beyond my own blog and because my blog sources are private since I like to edit and change my project structure constantly.

To trigger the build we just need:

a) A source with all the markdown files. In this case, my blog has a simple structure:

```
myblog/
├── misc
├── style
│   └── main.css
├── favicon.ico
├── img
├── index.md       # this is the landing page; this sets <in_main to true>
├── posts
│   ├── ...
│   ├── 2025       # markdown files in these directories are the content; these set <in_post to true>
│   └── 2026
├── robots.txt     # you want this to toss away those pesky AI crawlers
├── snippets
└── templates
    ├── footer.html.j2
    ├── header.html.j2
    └── menu.html.j2
```

b) There are some environment variables needed to run the script:

* `BASE_URL`      This is the Codeberg pages URL for my user
* `SRC`           This is the path to my source repository
* `DEST`          This is the path to my pages repository, defaults to "../pages"
* `YEAR`          This is the current year, defaults to the Year (yyyy) in the machine
* `YEAR_LOOKBACK` Years to look back, for my blog, it should be 2, so it builds from 2024 until 2026. Defaults to 1

These are defined in the Jenkinsfile as well, so pretty much all that I need to publish, it is controlled by these variables.

### Considerations

1. The year indexes are autogenerated. They will parse the month_year timestamp in the name of the file and sort their list using it. Anything under posts will be included as long a the title uses an `H3` header format.
2. Any file at root level or within another dir, e.g. `example/index.md` will have no footer unless it is included in the `INDEX_PAGES` environment variable. If included, the footer will include tracking and an anchor pointing to the landing page.
3. There is no direct map between the dropdown menu and the pages. If you add a new page and want it in the menu, you need to add a new entry in the `menu.html.j2` template.
4. The current build in the Jenkinsfile completes by publishing to [Neocities](https://neocities.org), you may opt to push to a different site or just use Codeberg pages, adapt the step accordingly
